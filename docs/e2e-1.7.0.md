# 1.7.0 端到端验证记录（DSH 桌面版 0.2.1-rc.3）

跑在隔离环境里，不碰真实 `~/.dsh`、不碰 app 本体、不往 `desktop` profile 装东西：

| | |
|---|---|
| DSH | 桌面版 `0.2.1-rc.3`（`dsh web` 形态，profile `e2e`） |
| 方式 | `DSH_HOME=/tmp/dsh-e2e-home`、`TMPDIR=/tmp/dsh-e2e/tmp`（spill 也隔离）、端口 53990 |
| 插件 | `dsh plugin --profile e2e add link:<repo>`（软链，每次启动都加载当前工作区代码） |
| 模型 | 本地假 LLM（OpenAI 兼容、零依赖，按消息里的标记决定回复：`#slow` / `#subagent` / `#fork` / `#nested` / `#remind` / `#job`），不联网 |
| 种子 | 243 个会话：普通 / 子代理 / `subagent_fork` / 孙代理 / 用户分叉 / 置顶 / 归档 / 带提醒 / 230 个会话的大分组 |
| UI 驱动 | headless Chromium + CDP（Node 原生 WebSocket，零依赖），截图在 `/tmp/dsh-e2e/shots/` |

复跑：`./start.sh --fresh` → `node e2e-run.mjs`（host 侧）、`node ui-e2e.mjs`（浏览器侧）。

- 浏览器 console 里与本插件相关的错误：无。（唯一一条 500 是场景 5 故意拦截 `precheck` 产生的，属预期。）

## 已知的测试盲区

- 假 LLM 只能造出「回合 / 子代理 / 后台任务 / 提醒」四类活动；审批与提问等待态（`pendingInteraction`）没有单独造，靠 `agent.status === 'running'` 与冒烟测试覆盖。
- 子代理的「删除中途再派生子代理」竞态只能靠归档后的 `agent/pre-step` 拦截来防御，没有做压力测试。
- 只在 macOS 上跑过；Windows 的 EBUSY 重试路径由冒烟测试（无权限目录 + 恢复）模拟，未在真实 Windows 上验证。
